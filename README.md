# Attention の O(n²) 問題と KV キャッシュ問題 — 研究系譜の調査

2018 年から 2026 年にかけて、Transformer の Attention が抱える二つのコスト問題に対して
どんな解決が試みられ、何が残って何が消えたのかを追跡した調査。**レビュー論文**と、
論文どうしの系譜を辿れる**インタラクティブな関係マップ**の二つからなる。

## この調査が答えようとしている問い

2018 年以降、Attention の計算量を改善する提案はおそらく 200 本を超えた。
そのうち、フロンティアの大規模言語モデルで既定の Attention 機構として採用されたものは、
**ひとつもない**。

これは失敗の物語ではない。問題が正しく定義されるまでに時間がかかり、定義され直した瞬間に
大量の研究が一斉に無効化され、別の場所で戦線が再形成された——という**問題定義の移動**の物語である。

すれ違いの核心は単純で、「Attention が重い」という一文が実際には四つの別々の主張を含んでいた。
本調査はすべての手法をこの 4 軸で分類して読む。

| 軸 | 問い | 達成する代表例 | 達成しない代表例 |
|---|---|---|---|
| **A. FLOPs** | 漸近計算量を下げたか | Linformer, Performer, Mamba | FlashAttention |
| **B. 実体化** | n×n をメモリに置かずに済むか | FlashAttention, Ring Attention | 素朴な Linformer 実装 |
| **C. 状態サイズ** | KV／再帰状態を劣線形にしたか | MLA, Mamba, StreamingLLM | FlashAttention, GQA |
| **D. 厳密性** | 出力が数学的に厳密か | FlashAttention, Ring Attention | ほぼ全ての近似手法 |

この軸で読むと、たとえば次のことが見えてくる。

- **FlashAttention は FLOPs を一切下げていない。** n² 個のスコアを全部計算する厳密な手法である。
  実体化を消して IO を下界まで削っただけで、近似的な O(n) 手法より実測で速くなった。
  これで第一波（2018–2022）の研究群の存在理由が消えた。
- **2024–2026 年は分岐ではなく収束である。** 厳密 Attention を層の 8〜27% に残すという構造で
  東西のラボが一致しており、分かれているのは各スロットに何を置くかだけである。

## レビュー論文に何が書いてあるか

| 章 | 内容 |
|---|---|
| 1 | **すれ違いの構造** — 上の 4 軸の導入 |
| 2 | **問題の定式化** — prefill と decode は別物である。KV サイズ式とデコードのローフライン |
| 3 | **第一波：近似の時代**（2018–2022） — 疎化・線形・再帰の 5 系統と、全滅した 6 つの理由 |
| 4 | **転回：FlashAttention** — FLOPs を下げずに IO 下界を達成し、近似の前提を消した |
| 5 | **戦場の移動：KV キャッシュ** — サイズ式の各項に対応する 6 系統と、圧縮の理論的下界 |
| 6 | **第二波：定数状態への再挑戦** — SSM／線形 RNN、SSD 双対性、二つの独立した壁 |
| 7 | **収束点：ハイブリッドという妥協**（2024–2026） — 二つのスロットとして解剖する |
| 8 | **評価の危機** — NIAH では見えない劣化、SCBench、Retrieval Head |
| 9 | **未解決問題** |
| 10 | **出典と検証状況** |

第 7 章がこの調査の到達点にあたる。ハイブリッドを「安価な多数派スロット」と
「厳密な少数派スロット」に分けて見ると、2025–2026 年の展開が一本の流れとして読める。

| 時期 | 多数派スロット | 少数派スロット |
|---|---|---|
| 2023–2024 | スライディングウィンドウ | フル MHA / GQA |
| 2024 | Mamba / Mamba-2, RG-LRU | フル Attention |
| 2025 | Gated DeltaNet, Lightning Attention | **MLA** |
| 2026 | KDA | **学習可能な疎 Attention**（DSA / QSA / MSA） |

比率だけを追うと、右列が三度入れ替わっていることが見えなくなる。

## 関係マップの使い方

195 本の論文を、**横軸に発表年、縦のレーンに研究系統**を取って配置し、系譜を辺で結んだもの。

### 軸と色の読み方

- **横軸** = 発表年（2018–2026）。年内の月まで反映している
- **縦のレーン** = 研究系統（11 本）。疎化 / 線形・低ランク / 再帰・外部メモリ / SSM・線形RNN /
  厳密カーネル / 分散・文脈並列 / KV アーキテクチャ / KV 事後圧縮 / サービングシステム /
  実運用モデル / 理論・評価
- **色** = その研究の**立場**。近似（FLOPs を減らすために厳密性を捨てる）/ 定数状態 /
  厳密（出力を変えず IO とメモリだけを削る）/ KV 圧縮 / システム / 実運用モデル / 理論・評価

軸ラベルは拡大率によらず常に同じ大きさで表示されるので、最大ズームアウトでも年とレーンが読める。

**マップの形そのものが物語を語る。** 左上（2018–2022 の近似手法）に密集していた点が、
2022 年以降は右下（KV 圧縮・システム・実運用モデル）へ移動していく。
これが「戦場の移動」の視覚的な表れである。

### 操作

| 操作 | 動作 |
|---|---|
| ノードをクリック | 詳細パネルが開き、**祖先と子孫がすべてハイライト**される |
| ドラッグ | 移動 |
| ホイール / ダブルクリック / `+` `-` | 拡大・縮小 |
| `0` キー / ⊡ ボタン | 全体表示に戻す |
| 検索ボックス | 名前で絞り込み |
| 色のチップ | その立場の研究だけを表示・非表示 |
| 系譜モード | 選択した論文に連なるノードだけを残す |

### 詳細パネルに出るもの

```
Mamba

         ため内容に基づく選択ができない点に求める。Δ・B・C を現在のトーク
         ンの関数とする選択的 SSM を導入してこれを解き…（150 字程度）

中核機構   Δ,B,C を入力の関数とする選択的 SSM。ハードウェア認識並列スキャン
限界・含意 状態は系列長によらず一定。対角・正固有値ゆえ parity 不可
```

源流・後継のチップはクリックでき、そのまま系譜を辿っていける。

### こう使うと役に立つ

- **ある手法の位置づけを知りたい** — 検索して選ぶと、何を受け継ぎ何に受け継がれたかが一望できる
- **系統をまるごと追いたい** — 起点の論文を選んで「系譜モード」を押すと、
  連なるノードだけが残る。たとえば `Linear Transformer`（2020）を選ぶと、
  Performer・RWKV・RetNet・GLA・Mamba-2・TTT まで枝が伸びるのが見える
- **ある立場だけ眺めたい** — 色チップで「理論・評価」だけを残すと、
  この分野が自分自身に下した判定（LRA、Zoology、Illusion of State、SCBench…）が並ぶ

## 収録範囲と、信頼できる度合い

| | |
|---|---|
| 収録論文 | 195 件 |
| 系譜の辺 | 214 本 |
| 論文の原題を特定できたもの | 194 / 195 |
| arXiv の一次ソース URL が確定するもの | 185 / 195 |

残る 10 件はブログ・GitHub・モデルカード・組織発表が出典で、**URL を推測せず空欄にしてある**。
機械可読な一覧は [`PAPERS.md`](PAPERS.md)（人が読む形式）と
[`data/papers.json`](data/papers.json) / [`data/papers.csv`](data/papers.csv) にある。

**構造的な主張と、個別の数値では信頼度が違う。** 4 軸の区別、prefill と decode の非対称性、
FlashAttention が FLOPs を下げていないこと、SSD 双対性、状態サイズと想起容量のトレードオフ、
評価の危機——これらは複数の独立した一次情報で裏付けている。

一方、最新世代のモデルの帰属と個別の数値は精度が落ちる。一次情報に到達できなかった項目には
本文中に `要確認` を付し（現在 10 箇所）、第 10 章にすべて列挙している。主なものは次の通り。

- **Qwen3.8-Max（2026-08）には専用の技術報告がない** — 根拠は公開 `config.json` と GitHub README のみ
- DeepSeek V4 の CSA / HCA は機構の定義が未確認（定量値のみ確認）。R2 は未公開
- IBM Granite 4.0、Llama 4 iRoPE、Qwen3.5 以降 — 一次技術報告を特定できず二次情報に依拠
- ByteDance Doubao / Seed 2.0 のアーキテクチャは情報空白

この調査は**確認できないものを埋めない**方針で作られている。論文名や著者を確認できなかったものは
空欄にしてあり、推測で埋めていない。また初版の誤り（Qwen 3.8 の実在、および 2026 年の中国勢を
「分岐」として立てた構成）は、削除せず**訂正として本文に明記**している。

第 7 章の後半が扱う 2025–2026 年の各社アーキテクチャは特に変動が速く、複数のラボが 1 年内に
2〜4 回の版更新を行っている。版番号と帰属は調査基準日時点のものとして読まれたい。

## 中身を編集したい場合

論文データは `map.html` が唯一の情報源で、`PAPERS.md` と `data/` はそこから生成する。

```bash
python3 tools/export_papers.py
```

データモデル、ノードの追加手順、守るべき方針、開発の進め方は
**[`AGENTS.md`](AGENTS.md)** にまとめてある。

```
.
├── review.html            レビュー論文本体            ← 正本
├── map.html               関係マップ（論文データを内包） ← 正本
├── PAPERS.md              収録論文一覧（レーン別）      ← 生成物
├── data/papers.json       構造化データ                ← 生成物
├── data/papers.csv        表計算・grep 用             ← 生成物
├── tools/export_papers.py 生成 + 整合性検査
├── AGENTS.md              引き継ぎ規約
└── notes/                 作業メモ（成果物ではない）
```
